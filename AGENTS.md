## Repository workflow

Before changing any Git repository:

- Read the repository's effective `AGENTS.md` files first. If the repository root has no `AGENTS.md`, create one before product-code edits and add this repository workflow section so the rules survive across agents and machines.
- Run `git fetch --all --prune`, then report the repository path, current branch, its upstream, worktree status, and the intended target branch before editing. Determine the target from the user's request, an open PR, the upstream default branch, or repository documentation; do not guess when those disagree.
- Work from the latest target branch. If the current branch can be fast-forwarded safely, update it. If local commits, dirty files, divergence, or an active worktree make updating destructive or ambiguous, preserve all work and ask one precise question instead of resetting, stashing, rebasing, force-updating, or switching branches silently.
- Open a separate Git worktree for the project and do the task there on a clearly named non-target branch based on the latest target branch. Keep the original workspace and its uncommitted changes untouched. State `current branch -> target branch` in the work plan and before a PR or merge.
- On this Mac, create Git worktrees ONLY under `/Volumes/gameWorkspace/worktrees`. Creating worktrees on the main volume or anywhere outside this root is forbidden, including repository-local `.worktrees`, home-directory, temporary-directory, and agent-managed replica paths.
- Before creating a worktree, read `git config --global --get worktree.root`; its required value on this Mac is `/Volumes/gameWorkspace/worktrees`. This is a custom policy key, not a Git built-in default or enforcement mechanism: always pass an explicit destination under this root to `git worktree add`, using a unique project/task directory.
- Verify that `/Volumes/gameWorkspace` is mounted on the external volume and that the resolved worktree destination remains under the required root, without a symlink redirect to the main volume. If the volume is unavailable, the setting differs, or the destination escapes the root, stop worktree creation and report the blocker; never fall back to the main volume or create an unmounted `/Volumes/gameWorkspace` directory there. Preserve existing worktrees and active sessions unless their migration or removal is explicitly requested.
- Commit frequently as work is completed: after each independently valid increment passes its relevant checks and manual QA, create the smallest atomic commit containing only that increment. Do not wait until the entire job is done to commit; never include unrelated dirty files or leave a verified user-requested change uncommitted unless the user explicitly says not to commit.
- Push each verified atomic commit to its configured upstream after confirming the destination branch. Never force-push or rewrite shared history without explicit approval.
- After the job is complete and the branch is pushed, open a pull request from the worktree branch into the confirmed target branch. Report the PR URL; do not stop at a local commit or pushed branch unless the user explicitly asks not to create a PR or the remote cannot accept one.
- Before handoff, fetch again and report whether the branch is ahead/behind the target, the exact commit(s), checks run, and the intended merge destination.
- After a task is finished and its merge into the intended target branch is confirmed, delete all completed worktrees and their local and remote feature branches belonging to that task. Verify that no uncommitted or unmerged work and no active session remain before deletion. Preserve unfinished worktrees, branches without confirmed merges, and branches used by other active tasks; never force removal to bypass these checks.
- Before finishing, enumerate and individually reassess every Git stash in the repository, including its staged, unstaged, and untracked changes. Apply and verify changes that are still needed, and drop a stash only after confirming its contents are safely preserved or already incorporated. Do not leave unresolved stashes at handoff: resolve ownership, conflicts, and uncertain discard decisions with the user first. Never use `git stash clear`, blindly pop stashes, or delete another active task's saved work merely to make the stash list empty. Verify `git stash list` is empty before declaring stash cleanup complete.

Project `AGENTS.md` files may add stricter repository-specific commands and branch policies, but must not weaken the safety rules above.
