# v0.5.2 마이그레이션

v0.5.2는 요청 거부 시점, 클라이언트 입력 오류, 라우트·컨슈머 등록 검증을 보정하는 패치 릴리스입니다. 공개 API 사용 방식은 유지되며, 잘못된 설정과 요청은 더 이른 단계에서 명시적으로 실패합니다.

## 요청 실행 순서

라우트 `Interceptor.PreHandle`은 DTO, 폼, 멀티파트와 경로 인자를 해석하기 전에 실행됩니다. 인증되지 않은 요청은 컨트롤러뿐 아니라 요청 본문 해석도 시작하지 않습니다. 인터셉터는 해석된 컨트롤러 인자에 의존하지 않아야 합니다.

잘못된 JSON·폼·멀티파트와 `path.Int`, `path.Boolean` 변환 오류는 HTTP 400으로 응답합니다. `MaxBodyBytes` 초과는 기존대로 HTTP 413입니다.

## 시작 단계 검증

`App.Validate`는 nil 또는 유효하지 않은 HTTP 라우트 핸들러를 `Routes[n].Handler` 문제로 보고합니다. 실행 중 reflection panic 대신 배포 전 검증에서 원인을 확인할 수 있습니다.

동일한 consumer topic을 두 번 등록하면 `Consumers().Register`가 오류를 반환합니다. 현재 consumer 라우팅은 topic마다 하나의 핸들러를 지원하므로 모든 등록 오류를 확인하십시오.

## CORS와 쿠키

CORS 인터셉터는 `Origin`과 `Access-Control-Request-Method`가 모두 있는 실제 preflight 요청만 204로 종료합니다. 일반 `OPTIONS` 요청은 등록된 라우트 핸들러로 전달됩니다.

삭제 쿠키는 `Max-Age=0`과 과거 `Expires`를 함께 사용하고 HTTP 날짜를 GMT로 직렬화합니다. 쿠키 삭제 API의 호출 방식은 바뀌지 않습니다.

## context 기반 종료

`App.RunContext(ctx, options)`가 추가되었습니다. 기존 `App.Run(options)`은 그대로 사용할 수 있으며, 테스트·서비스 호스트에서 process signal 대신 context 취소로 정상 종료하려면 `RunContext`를 사용하십시오.
