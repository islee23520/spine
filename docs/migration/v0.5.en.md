# v0.5 secure-default migration

> Also review the [v0.5.1 corrective migration](v0.5.1.en.md) for lifecycle and delivery fixes. The existing v0.5.0 tag remains immutable.

v0.5 strengthens broker transport, WebSocket, CORS, consumer failure, and cookie defaults. `App.Validate(options)` reports every network-free configuration issue as `*boot.ConfigError`; `App.Run` performs the same preflight automatically.

## Pre-response interceptor lifecycle

`core.Interceptor` now requires `BeforeResponse(ctx, meta, executionErr) error`. This is an alpha API break, so every interceptor implementation must add the method.

The pipeline preserves Controller-returned errors and post-execution hook failures, then invokes `BeforeResponse` in reverse order for route and global interceptors whose `PreHandle` succeeded. A success response is written only after every pre-response finalizer succeeds. Use `PreHandle` to begin a request transaction, `BeforeResponse` to commit or roll back it, and `AfterCompletion` for post-response observation and cleanup.

```go
func (i *TxInterceptor) BeforeResponse(
    ctx core.ExecutionContext,
    meta core.HandlerMeta,
    executionErr error,
) error {
    tx, ok := transactionFrom(ctx)
    if !ok {
        return nil
    }
    if executionErr != nil {
        return tx.Rollback()
    }
    return tx.Commit()
}
```

## Brokers

Kafka readers and writers use Spine's implicit TLS 1.2+ configuration by default. Set `KafkaOptions.TLS`, `Dialer`, or `Transport` only for custom CA, mTLS, SASL, or dial behavior. Plaintext local development must set `AllowInsecureTransport: true`.

RabbitMQ requires an `amqps://` URL by default. Use `amqp://` with `AllowInsecureTransport: true` only in an isolated local environment.

RabbitMQ handler failure now defaults to `RabbitMqFailureReject`. Configure a pre-provisioned DLX when rejected messages must be retained:

```go
Read: &boot.RabbitMqReadOptions{
    Exchange:      "events",
    FailurePolicy: boot.RabbitMqFailureReject,
    DeadLetter: &boot.RabbitMqDeadLetterOptions{
        Exchange:   "events.dlx",
        RoutingKey: "events.failed",
    },
}
```

The v0.4.3 RabbitMQ consumer always handled a handler failure with `NACK(requeue=true)`. `RabbitMqReadOptions` did not have a `RequeueOnError` field in that release. To preserve the v0.4.3 requeue behavior in v0.5, configure it explicitly:

```go
FailurePolicy: boot.RabbitMqFailureRequeue,
```

This compatibility setting can redeliver a poison message indefinitely. For new v0.5 deployments, the recommended configuration is `RabbitMqFailureReject` with a DLX, as shown above. Rejected messages are dead-lettered when the queue has a DLX; without one, the broker may discard them. Operators must pre-provision the DLX exchange, and existing queues with different arguments can fail with a RabbitMQ queue precondition error, so align the topology before deployment. The v0.5 `RequeueOnError` field is only a temporary compatibility path and is deprecated; new code should use `FailurePolicy`.

Dispatch uses AMQP `RoutingKey`, not producer-controlled `Type`.

Transport read failures close and rebuild the reader with configurable exponential backoff and jitter through `ConsumerRetryOptions`. This is independent from handler ACK/NACK behavior.

## HTTP and WebSocket

`App.Interceptor` applies to HTTP and WebSocket. Use `InterceptorFor(boot.InterceptorHTTP|InterceptorWebSocket|InterceptorAll, ...)` for an explicit scope.

### Duplicate registrations of the same interceptor

v0.5 does not deduplicate global interceptors by concrete type alone.

- Registering the same pointer instance for multiple scopes merges the scopes and executes that instance once.
- Distinct pointer instances execute independently even when they have the same concrete type.
- Repeated typed-nil placeholders of the same type merge and share the container singleton.
- Value-type interceptors remain independent registrations.

Reuse the same pointer when scopes must share state; register distinct instances when same-type policies must run independently.

WebSocket default origin checks require both scheme and host to match. Prefer exact `AllowedOrigins`. Forwarding headers affect the public scheme only when the direct peer belongs to `TrustedProxyCIDRs`; trusted proxies must remove or overwrite client-supplied forwarding headers.

The default WebSocket capacity is `DefaultWebSocketMaxConnections` (1024). Use a positive value or `UnlimitedWebSocketConnections`. Capacity rejection occurs before upgrade and returns HTTP 503, `Retry-After`, and `WEBSOCKET_CAPACITY_EXCEEDED` JSON.

Negative HTTP/WS timeouts and bounded sizes now fail preflight. `HTTPOptions.MaxBodyBytes < 0` remains the documented explicit body-limit opt-out.

## CORS and cookies

Wildcard origins with credentials are invalid. Prefer `cors.NewValidated` so startup can report the structured error. Legacy `cors.New` remains source-compatible and fails before writing response headers.

All built-in response handlers validate every cookie before writing headers, status, or body. Invalid fields are rejected instead of silently modified. Encode arbitrary Unicode or delimiter-containing values explicitly with `httpx.EncodeCookieValue` and decode with `httpx.DecodeCookieValue`.
